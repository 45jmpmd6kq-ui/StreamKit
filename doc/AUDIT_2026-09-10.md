# Audit StreamKit 0.12.0 — 10 septembre 2026

Périmètre : tout `src/` (noyau, core, dashboard, 5 modules et leurs overlays/pages), `tests/`, CI, `package.json`, chaîne de build. Angles : sécurité, robustesse/performance, upgradabilité.

Méthode : lecture intégrale du code, `npm test`, `npm audit`, `npm outdated`, et une sonde HTTP contre le routeur pour confirmer deux comportements suspects (script conservé hors dépôt).

## Résumé

L'état général est **sain** : 54 tests verts, 0 vulnérabilité npm, dépendances à jour (Electron 44.3.0, Twurple 8.1.4, electron-updater 6.8.9, electron-builder 26.15.3). L'architecture est solide : séparation code/données, contrat de module documenté, garde-fous serveur (CSRF, rebinding DNS, traversée de dossier, XSS sur la page OAuth) chacun couvert par un test.

Deux vrais bugs ont été trouvés et **reproduits** :

| # | Gravité | Constat |
|---|---|---|
| S1 | **Critique** | N'importe quelle page web peut tuer StreamKit en plein live (une balise `<img>` suffit). |
| S2 | Moyen | Une URL mal encodée laisse la connexion pendue sans réponse. |

Le reste relève du durcissement et de la dette maîtrisable. Plan d'action en fin de document.

## 1. Sécurité

### S1 — Plantage à distance depuis une page web (critique, reproduit)

`src/core/serveur.js:97-106`, `servirFichier` : après `existsSync(cible)`, le fichier est servi par `createReadStream(cible).pipe(res)` **sans gestionnaire `error`**. Si `cible` est un dossier (par ex. `/overlay/roue-rl/roue/cars`, le dossier des icônes), le flux émet `EISDIR` → exception non rattrapée.

- Sous `npm run dev`, `index.js` installe `process.on('uncaughtException')` : la ligne est journalisée, mais la réponse HTTP n'est jamais envoyée (connexion pendue).
- Sous Electron, **`main.js` n'installe pas ce gestionnaire** (seulement `unhandledRejection`) : Electron affiche sa boîte d'erreur et le processus meurt. Icône, bot, overlays, tout s'arrête.

Exploitation : un `<img src="http://127.0.0.1:4455/overlay/roue-rl/roue/cars">` sur un site quelconque ouvert par le streamer. Les requêtes d'image n'envoient pas d'en-tête `Origin`, et `Host` est légitime : les deux gardes passent.

Reproduit par la sonde : `UNCAUGHT EXCEPTION : EISDIR` puis « aucune réponse en 3 s ».

Correctif (trois lignes) :
1. remplacer `existsSync` par `statSync(cible, { throwIfNoEntry: false })?.isFile()` ;
2. `createReadStream(cible).on('error', () => texte(res, 500, 'Lecture impossible')).pipe(res)` ;
3. dans `main.js`, ajouter `process.on('uncaughtException', (e) => log.err(...))` comme dans `index.js`.

Puis un test dans `serveur.test.js` (« un dossier demandé comme fichier répond 404, sans exception »).

### S2 — Connexion pendue sur URL mal encodée (moyen, reproduit)

`serveur.js:160` : `decodeURIComponent(url.pathname)` est appelé **avant** le `try` (ligne 174). `/overlay/%E0%A4%A` lève `URIError`, le handler async rejette, la réponse ne part jamais. Reproduit : `UNHANDLED REJECTION : URIError`.

Correctif : envelopper le décodage et répondre 400.

### S3 — Secrets en clair sur le disque (moyen)

`tokens.json` contient les secrets client Twitch et Spotify et les jetons de rafraîchissement, en JSON lisible. Le dossier `%APPDATA%` est protégé par les ACL utilisateur, mais tout programme lancé par le streamer y lit.

Piste : chiffrer les valeurs avec `safeStorage` d'Electron (DPAPI sous Windows), injecté dans le noyau comme l'est déjà l'updater. En ligne de commande, repli en clair. Format : préfixe `enc:` + base64, migration transparente à la première écriture.

### S4 — Spotify : PKCE supprime le secret client (amélioration)

Spotify supporte *Authorization Code + PKCE* et rafraîchit le jeton avec le seul `client_id`. Conséquences : le streamer ne saisit plus qu'un identifiant, plus de secret Spotify à stocker, assistant plus court. Le connecteur porterait un `type: 'pkce'`. Twitch n'offre pas PKCE : inchangé.

### S5 — `state` OAuth tiré de `Math.random` (faible)

`auth.js:80`, `connecteurs.js:133`. Remplacer par `crypto.randomBytes(16).toString('hex')`. Risque réel faible (flux local), correctif trivial.

### S6 — Durcissement Electron (faible à moyen)

- **Pas de garde `will-navigate`** : si le dashboard navigue (lien sans `target=_blank`, redirection), la fenêtre chargerait un site externe. Bloquer tout ce qui n'est pas `http://127.0.0.1:<port>`.
- **`setWindowOpenHandler` → `shell.openExternal(url)` sans filtre de schéma** : n'accepter que `http:` et `https:`.
- **Aucune CSP** sur le dashboard ni les overlays. Ajouter un en-tête `Content-Security-Policy` côté serveur : `default-src 'self'; connect-src 'self'; img-src 'self' data: https://media.valorant-api.com; frame-ancestors 'none'; object-src 'none'; base-uri 'none'`. Les scripts inline des overlays imposent `script-src 'self' 'unsafe-inline'` (ou des nonces).
- **Fuses electron-builder** (supportées en 26.x, clé `electronFuses`) : `runAsNode: false`, `enableNodeOptionsEnvironmentVariable: false`, `enableNodeCliInspectArguments: false`. Avec `asar: true`, ajouter `enableEmbeddedAsarIntegrityValidation` + `onlyLoadAppFromAsar`.
- **`asar: false`** est là depuis le passage à Electron, sans raison consignée. Electron patche `fs` : `readdirSync`, `import()`, `createReadStream` et `statSync` lisent dans l'ASAR. À recetter avec un vrai build avant de basculer.

### S7 — Comparaison de préfixe sans séparateur (faible)

`servirFichier` : `cible.startsWith(normalize(base))` accepterait un dossier frère commençant par le même nom (`overlay` vs `overlay-bis`). Non exploitable aujourd'hui. Comparer avec `base + sep`.

### S8 — Injection de lignes dans le journal (faible)

Une saisie viewer contenant `\n` produit de fausses lignes dans le fichier du jour. Dans `journal.texte()`, remplacer `[\r\n]+` par un espace.

### S9 — `Sec-Fetch-Site` (optionnel)

Chromium, Firefox et le CEF d'OBS envoient cet en-tête. Refuser `cross-site` ajoute une barrière indépendante d'`Origin`. À laisser passer quand absent (clients non-navigateur).

## 2. Robustesse et performance

### P1 — `fetch` sans délai d'attente (moyen)

Sans `AbortSignal.timeout`, un appel qui pend bloque ce qui l'attend :

| Fichier | Appel | Conséquence |
|---|---|---|
| `auth.js:48, 136` | validation réseau, échange du code | autorisation Twitch bloquée jusqu'au délai de 5 min |
| `connecteurs.js:180, 214` | jeton, profil Spotify | idem |
| `maj.js:70` | GitHub | vérification de MAJ figée |
| `spotify.js:108, 136` | jeton et toute l'API | **bot musique gelé sans erreur** : l'intervalle saute les tics tant que le tour précédent tourne |

Le module Valorant fait déjà `AbortSignal.timeout`. Correctif uniforme : un helper `fetchAvecDelai(url, options, ms = 15000)` dans `core/`.

### P2 — `appendFileSync` à chaque ligne de journal (faible)

Écriture disque synchrone sur la boucle d'événements qui sert aussi le chat. Volume faible, acceptable. Si besoin : `createWriteStream({ flags: 'a' })` réouvert au changement de jour. Conserver le synchrone si l'on tient à avoir la ligne sur disque avant un crash.

### P3 — Menu de l'icône reconstruit toutes les 5 s (faible)

`main.js:257-296` : `Menu.buildFromTemplate` + `setContextMenu` même sans changement. Mémoriser le résumé et ne reconstruire qu'à la différence, sinon le menu se referme sous la souris du streamer.

### P4 — Écriture atomique sans `fsync` (faible)

`store.ecrireAtomique` et `compteurs.ecrire` : écriture puis `rename`. Sans `fsyncSync(fd)` avant le `rename`, une coupure de courant peut laisser un fichier vide après renommage. Coût négligeable, fichiers rarement écrits.

### P5 — Dashboard : quatre appels toutes les 5 s (correct)

`/api/etat`, `/api/modules`, `/api/sante`, `/api/connecteurs`. Local, santé des modules mise en cache 20 s, arrêt quand la fenêtre est masquée : bien conçu. Possible fusion en un seul point ou en SSE, non prioritaire.

### P6 — État EventSub déclaré, pas mesuré (faible)

`twitch.js:138` pose `eventsubConnecte = true` sans écouter. Twurple expose `onUserSocketConnect` / `onUserSocketDisconnect` : la vue d'ensemble affirme « EventSub connecté » sans le savoir.

### P7 — Cache-buster `?v=Date.now()` sur l'import des modules (faible)

`registre.js:74`. `charger()` n'est appelé qu'une fois : le paramètre est sans effet utile, et casse le cache ESM. Si `charger()` était rappelé, les modules à état de fichier (`voitures.js` et son cache, l'agent HTTPS de `riot.js`) seraient instanciés deux fois. Retirer, ou rendre `charger` idempotent.

### P8 — Contexte fantôme sur module arrêté (faible)

`noyau.js:600, 684` : `contextes.get(id) ?? fabriquerContexte(m)` enregistre un contexte pour un module arrêté ; au démarrage suivant, `contextes.set` l'écrase sans `_nettoyer()`. Sans effet aujourd'hui (aucune action ne pose de minuteur), piège pour un futur module. Créer un contexte jetable et le nettoyer après l'action.

## 3. Upgradabilité et maintenabilité

### U1 — La logique métier pure n'a aucun test (élevé, peu coûteux)

Ces fonctions sont pures ou presque, testables sans mock, et ce sont exactement celles qu'un refactor casse :

- `musique/file.js` : statuts, `trouverAAnnuler`, `marquerEnLecture`, `elaguer` ;
- `musique/spotify.js` : `looseMatch`, scoring de `searchTrack` (extraire la fonction de score) ;
- `roue-rl/roue.js` : `avoidRepeat`, sac de tirage, purge des voitures retirées ;
- `roue-rl/voitures.js` : `normaliser`, `resoudre`, `nettoyer` ;
- `valorant/session.js` : `enregistrer`, `aConfirmer`, `blocSession` (série, nuls, placements) ;
- `clips/clips.js` : restauration du titre en cas d'échec (avec un faux `api`).

À ajouter aussi : tests serveur pour S1/S2 une fois corrigés ; test de `noyau` vérifiant qu'arrêter un module coupe ses minuteurs et retire ses abonnements.

### U2 — Ni lint ni formateur

Aucun ESLint, Prettier ni `.editorconfig`. Ajouter ESLint (flat config, `recommended`, globals navigateur pour `dashboard/` et les HTML) + Prettier, et `npm run lint` dans la CI. Gain rapide : variables mortes, `await` oubliés, globals implicites dans les overlays.

### U3 — `noyau.js` concentre trop (moyen)

Près de 800 lignes ; l'objet `app` mêle santé, connecteurs, Twitch, réglages généraux, MAJ. Sortir au minimum `sante()` et `etatConnecteurs()` dans `core/sante.js`, en leur passant `registre`, `twitch`, `connecteurs`, `diffusion`.

### U4 — Réglage mort : `maj.depot`

Sous Electron, le dépôt vient de `build.publish`. `CONFIG_DEFAUT.maj.depot`, `etatGeneral.depotMaj` et `/api/reglages { depotMaj }` survivent sans effet (le dashboard ne l'envoie plus, `app.js:1161`). Ne sert qu'à `maj.js` en CLI. Retirer de l'état et de l'API, ou l'annoter « CLI seulement ».

### U5 — Migration de config inline dans le démarrage

`noyau.js:736-745` : la migration 1→2 vit au milieu du démarrage. Un tableau `MIGRATIONS_CONFIG` dans `store.js`, appliqué par `chargerConfig()` comme `schema.migrer` pour les modules. La prochaine sera propre.

### U6 — L'updater Electron compare les versions par `!==` (faible, bug)

`main.js:98` : `dispo: derniere !== actuelle`. Une release plus ancienne que l'installée (rollback, tag retiré) afficherait « Mettre à jour » vers une version inférieure ; electron-updater refuserait (`allowDowngrade` faux), mais le bouton mentirait. `maj.comparer` existe et est testé : `comparer(derniere, actuelle) > 0`.

### U7 — `echapper()` recopié huit fois

`app.js`, `auth.js` et six fichiers HTML. Soit servir `/commun/esc.js` (dashboard et overlays), soit assumer la duplication au nom de l'autonomie des overlays, mais alors un test qui vérifie que chaque HTML injectant des données viewer via `innerHTML` passe par `esc(`.

### U8 — Dashboard : listeners rattachés à chaque rendu

`dessinerRail`, `brancherConnecteurs`, `dessinerDetail` reparcourent le DOM après chaque `innerHTML`. La délégation (`#liste-modules` écoute `click` et lit `closest('[data-module]')`) supprime ce code et le risque d'empilement, déjà rencontré sur `#btn-sauver` (`app.js:889-896`).

### U9 — Tag git `v0.12.0` absent localement

`git tag` s'arrête à `v0.11.0` alors que la 0.12.0 est publiée. `git fetch --tags` pour rapatrier celui créé par electron-builder, sinon le prochain `npm version patch` repart d'un dépôt sans tag pour cette version.

### U10 — `livraison/builder-effective-config.yaml` périmé

Daté du 8 septembre, `electronVersion: 33.4.11`. L'installeur 0.12.0 du 10 septembre est bien en Electron 44 (`builder-debug.yml` du même jour). Fichier trompeur : à supprimer, `livraison/` est ignoré par git.

## 4. Ce qui tient bien (à préserver)

- Séparation code/données ; écriture atomique ; BOM toléré ; fichier corrompu mis de côté plutôt que fatal.
- Serveur : contrôle `Host` (rebinding), `Origin` (CSRF), `Content-Type` JSON, traversée bloquée, page OAuth échappée, corps limité à 512 Ko. Chaque garde a son test.
- Écoute strictement locale (`127.0.0.1` et `::1`), jamais `0.0.0.0`.
- Renderer sans Node, `contextIsolation`, liens externes vers le vrai navigateur.
- Minuteurs suivis, tours jamais chevauchés, abonnements Twitch retirés par module.
- Caches fondés sur `mtime` (jetons, catalogue), version lue une fois.
- Mise à jour : sha512 vérifié par electron-updater, `autoDownload` faux, release publiée et non brouillon, démontage complet avant `quitAndInstall`.
- Journal : erreurs updater condensées, rétention 14 jours, tampon borné.
